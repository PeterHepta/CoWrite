# 详细设计一：WebSocket 消息调度机制

## 1. 概述

CoWrite 的前后端通信基于 WebSocket，所有消息均为 JSON 格式，以字符串字段 `type` 作为消息类型标识（调度键）。  
后端的 `Session::on_read()` 与前端的 `handleMessage()` 分别充当服务端和客户端的**消息分派中心**，其作用类似于操作系统中的消息泵（Message Pump）与消息处理函数（WndProc / Handler），或 Qt 中的信号槽映射表。

---

## 2. 整体消息流结构

```
[客户端 UI 事件]
    │  btn.onclick → ws.send(JSON)
    ▼
[WebSocket 信道]
    │
    ▼
[服务端 Session::on_read()]          ← 消息泵 / 分派入口
    │   解析 JSON，读取 data["type"]
    │
    ├── joined_ == false (未入房间状态)
    │       ├── "register"         → db_task: INSERT users
    │       ├── "login"            → db_task: SELECT users → register_user()
    │       ├── "create_room"      → db_task: generate_unique_code_db / insert_invite_db
    │       ├── "join_with_code"   → db_task: SELECT invite_codes → stmt_use_code_
    │       ├── "join"             → room_->join(this) + db_task: 记录成员 + send_history
    │       ├── "rejoin_room"      → db_task: 校验成员 → room_->join(this) + send_history
    │       └── "get_my_rooms"     → db_task: SELECT room_members JOIN invite_codes
    │
    └── joined_ == true (已入房间状态)
            ├── "gen_invite"         → db_task: 校验 owner + generate_unique_code_db
            ├── "rename_room"        → db_task: UPDATE invite_codes SET room_name
            ├── "get_room_members"   → db_task: SELECT members + 回 io 线程查在线状态
            ├── "save_snapshot"      → db_task: INSERT saves
            ├── "quicksave_snapshot" → db_task: DELETE quick + INSERT saves
            ├── "get_saves"          → db_task: SELECT saves
            ├── "load_save"          → db_task: 清空 events + 重写 events + broadcast_all
            ├── "delete_save"        → db_task: DELETE saves + broadcast_except
            ├── "submit_auto_snapshot" → db_task: 插入自动快照 + 清空 events
            ├── "cursor" / "presence"  → room_->broadcast_except(this, payload)
            └── [其他类型]             → room_->save_event(payload) + broadcast_except
```

## 3. 消息函数列表（服务端"槽"）

> 对应关系：消息 `type` 字段 → 执行逻辑（"槽函数"）

| 消息 type | 触发阶段 | 服务端处理逻辑 | 响应消息 type |
|-----------|---------|--------------|--------------|
| `register` | 未入房 | SHA-256 密码 → INSERT users | `register_res` |
| `login` | 未入房 | SELECT users 验证 → register_user() 踢旧连接 | `login_res` |
| `create_room` | 未入房 | generate_doc_id → generate_unique_code_db → insert_invite_db | `create_room_res` |
| `join_with_code` | 未入房 | SELECT invite_codes 校验有效期/使用次数 → stmt_use_code_ | `join_with_code_res` |
| `join` | 未入房 | get_or_create_room → join → INSERT member → send_history → broadcast presence | `init` + `history_batch`/`snapshot_init` |
| `rejoin_room` | 未入房 | 校验 room_members → join → send_history → broadcast presence | `init` + `history_batch`/`snapshot_init` |
| `get_my_rooms` | 未入房 | SELECT room_members JOIN invite_codes | `get_my_rooms_res` |
| `gen_invite` | 已入房 | 校验 owner → generate_unique_code_db → insert_invite_db | `gen_invite_res` |
| `rename_room` | 已入房 | 校验 owner → UPDATE invite_codes SET room_name | `rename_room_res` |
| `get_room_members` | 已入房 | SELECT members → 回 io 查在线状态 | `get_room_members_res` |
| `save_snapshot` | 已入房 | INSERT saves (is_quick=0) | `save_snapshot_res` |
| `quicksave_snapshot` | 已入房 | DELETE quick saves → INSERT saves (is_quick=1) | `save_snapshot_res` |
| `get_saves` | 已入房 | SELECT saves ORDER BY is_quick DESC | `get_saves_res` |
| `load_save` | 已入房 | DELETE events → INSERT events(insert) → INSERT events(shape_add) → broadcast_all | `load_save_applied`（广播） |
| `delete_save` | 已入房 | DELETE saves → 发送者 res + broadcast_except | `delete_save_res` + `save_deleted`（广播） |
| `submit_auto_snapshot` | 已入房 | INSERT auto_snap → DELETE events → DELETE old_auto_snaps → room.reset_snapshot_state | 无（内部） |
| `cursor` | 已入房 | room_->broadcast_except | `cursor`（广播） |
| `presence` | 已入房 | room_->broadcast_except | `presence`（广播） |
| `insert` / `delete` / `format` / `shape_*` / `ops_batch` | 已入房 | save_event → broadcast_except | 原样广播 |

## 5. 线程与执行上下文切换

后端所有数据库操作必须在 `db_thread_` 上执行，IO 操作在 `io_context` 线程上执行。消息分派时涉及两次上下文切换：

```
io_thread (on_read)
   │
   ├── post_db_task(lambda)   ← 投递到 db_thread_
   │        │
   │        ▼
   │    db_thread_ (db_worker_loop)
   │        │  执行 SQL
   │        │
   │        └── net::post(ws_.get_executor(), lambda)  ← 回切到 io_thread
   │                    │
   │                    ▼
   │              io_thread (send / broadcast)
   ▼
（继续 do_read，等待下一条消息）
```

> 规则：凡操作 `stmt_*` 预编译语句的代码，必须在 `db_thread_` 执行；  
> 凡操作 `Session` 成员（`username_`、`room_`、`ws_`）的代码，必须在对应 `io_context` 线程执行。

## 6. 发送批量聚合机制（Write Batching）

`Session::send()` 并不直接写 WebSocket，而是投入 `pending_` 队列，由 2ms 定时器触发 `flush()`：

```
send(msg)
  │
  └── enqueue(msg)
          ├── pending_.push_back(msg)
          └── 若未 writing 且未 armed → arm_timer()
                      │
                      └── 2ms 后 → flush()
                                    ├── pending_.size() == 1 → 直接发
                                    └── pending_.size() > 1  → 打包为 {"type":"batch","msgs":[...]}
                                                                   │
                                                                   └── ws_.async_write → on_write
                                                                               │
                                                                               └── 若仍有 pending_ → flush()
```

客户端 `ws.onmessage` 对应解包：收到 `batch` 类型时，拆包逐条调用 `handleMessage`。
